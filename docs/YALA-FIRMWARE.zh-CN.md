# YALA RD03v2 定制实验固件

仅适用于 Qualcomm IPQ5018 + QCN6122 的小米 AX3000T RD03v2。
**不是 MediaTek RD03/RD23 固件，也不是原作者的正式发行版。**

当前产物用于审查和测试，尚未实机启动、回归吞吐或断电恢复测试。
GitHub 构建不会连接或刷写路由器，不自动发布 Release 或软件源。

## 改动范围

- 基于原作者 v2.1.0，纳入无线接收停滞、UDP 触发固件崩溃和 NSS 无线恢复修复，
  保留低内存缓冲配置。新版仍需实机回归，不能据此确认历史故障原因。
- CPU 频率上限保持芯片额定的 1008MHz，不使用新版上游默认的 1296MHz 超频；
  不提高用户已经设置得更低的频率上限。
- ucode 使用 OpenWrt 官方 2026-10-23 的固定配方，ABI 20261009；
  从干净源码重编译 netifd、wpad、rpcd、模块和 LuCI，去掉混装依赖的前提。
- 安装包数据库中全部已安装软件按版本固定，配套签名包一并提供。
  不要运行 `apk upgrade` 或单独强制替换 ucode/无线组件。
- 预装 OpenClash 0.48.002，自带进程环境 GOGC=50、GOMEMLIMIT=32MiB。
  首次启动保持代理关闭，流媒体自动解锁关闭、进程匹配关闭、国内 IPv4 绕过开启。
- zram 逻辑容量 64MiB、压缩数据物理上限 24MiB，开机启用。
  它不能等同新增物理内存，也不保证高负载绝不卡顿。
- 首次启动使用 223.5.5.5 / 1.1.1.1 作为直连 DNS，配置代理后再由插件接管。
  不内置个人 SSID 密码、WAN 账户、订阅、节点、控制密钥。

## 为什么核心单独提供

Mihomo 1.19.33 官方 arm64 核心约 55MB 解压体积，不放入 RAM 安装镜像。
它作为同一签名包集合中的 `mihomo-yala` 提供，先完成 NAND 固件安装，
再安装配套核心、恢复配置并从 LuCI 启用 OpenClash。
避免升级过程中 RAM 安装环境先被大二进制占满。

## 产物与验证

Actions 产物包含永久固件、两组 RAM 安装镜像、配套 APK 集合、
SHA256、公钥、构建溯源和 `yala-verification.json`。
原作者的镜像/设备树/内核模块/签名验证继续运行；另用 QEMU 检查实际 arm64
根文件系统的 ucode 模块导入、关键二进制依赖以及新 ABI 的一致性。
这些检查不能替代真实无线硬件测试。

工作流将源码准备、编译和镜像验证分别展示。下载、编译器、主机工具及交叉工具链
缓存会在编译后保存；验证失败不再导致这些缓存丢失。另保留两天的
`UNVERIFIED-RD03v2-debug-*` 供定位问题，它不代表验证通过，也不是交付固件。
只有全部镜像检查通过才生成 `YALA-RD03v2-experimental-*`。

固件内的定制软件源 URL 是预留位置，尚未部署。
**软件源发布、实机恢复方案和备份审查完成前，不应刷写这些实验镜像。**

## 升级前的后续步骤

1. 保存现有配置备份、固件和可恢复的 NAND/安装镜像，另存到路由器以外。
2. 准备有线连接、正确硬件版本和回退方案。
3. 核对签名与校验和，并部署同版的软件源或准备离线签名 APK。
4. 按原作者规定进入 RAM 安装环境，验证后才从那里执行 sysupgrade。
   不能直接在当前 NAND 系统执行固件刷写。
5. 首次 NAND 启动先验证 Wi-Fi、DNS、内存、重启和直连吞吐，
   再安装配套核心、恢复代理配置，最后验证代理流量和持续播放。
